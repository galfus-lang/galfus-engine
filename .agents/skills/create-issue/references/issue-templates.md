# Galfus Issue Templates

The original templates from `.github` are copied locally as `bug_report.yml`, `feature_request.yml`, and `support.yml` so this skill does not depend on that repository being present.

## Bug Report

See [bug_report.yml](bug_report.yml) for the exact form.

- Title prefix: `[Bug] `
- Default labels: `bug`, `needs-triage`
- Required fields: Summary, Problem to Solve, Proposed Solution, Scope of Impact, Priority, and confirmations for duplicate/Discussion search and Code of Conduct.
- Optional field: Contact Details.

Use this when behavior is incorrect, unexpected, or prevents intended use. State the observed problem before proposing a fix.

## Feature Request

See [feature_request.yml](feature_request.yml) for the exact form.

- Title prefix: `[Feature] `
- Default labels: `enhancement`, `needs-triage`
- Required fields: Summary, Problem to Solve, Proposed Solution, Scope of Impact, Priority, and confirmations for duplicate/Discussion search and Code of Conduct.
- Optional fields: Alternatives Considered, Expected Benefits, Risks / Drawbacks, and Contact Details.

Use this for a new capability or a deliberate improvement to existing behavior.

## Support / Question

See [support.yml](support.yml) for the exact form.

- Title prefix: `[Support] `
- Default labels: `question`, `needs-triage`
- Required fields: Question Summary, Context, and confirmations for duplicate/Discussion search and Code of Conduct.
- Optional fields: What Have You Tried?, Environment, and Contact Details.

Use this for help, clarification, or general questions. Redirect apparent bugs and feature requests to their respective templates.

## Scope of Impact

Bug and feature issues must select one or more of:

- Core / Runtime
- CLI
- Web / Frontend
- Performance
- Security
- Documentation
- Tooling
- Ecosystem (Packages, Integrations)
- Other

## Priority

Bug and feature issues must select one:

- Critical (blocks usage)
- High (strongly improves workflow)
- Medium (nice to have)
- Low (minor enhancement)

## Confirmations

The templates require confirmation that the author searched existing issues and Discussions and agrees to follow the Code of Conduct. Do not represent either confirmation as complete without explicit evidence from the user.
